# 扫描模块 · 功能方案

- 版本：V1.0
- 日期：2026-11-13

---

## 1. 定位

**考研系统**负责组卷、发布考试、批改、成绩管理；**扫描模块**负责补上线下作答这一环：

1. 根据考研系统发来的考试和题目信息，生成答题卡，并支持设计、调整；
2. 考后用扫描仪扫描答题卡或导入 PDF，识别出每个学生每道题的作答；
3. 处理完、核对完后，把结果统一同步给考研系统批改。

适用两种场景，用的是同一套客户端和流程：

- **学校批量扫描**：一场考试的答题卡成批扫描；
- **学生单张扫描**：学生自己写完一张卡，拿到扫描电脑上单独扫描。

## 2. 总原则

1. **现场能解决的，在客户端当场解决**：缺页、扫糊、混卡这类问题，客户端当场报出来，老师在扫描仪前直接重扫、补扫、调整。
2. **扫描模块内部处理完、核对完，再统一同步给考研系统**：期间不往考研系统送数据。现场解决不了的卷子作为异常数据一起同步，由考研系统人工补全。回传本身不设时间限制。
3. **每份卷子的结果只出一版**：可以重复同步，但不会重复入库。
4. **不能悄悄出错**：没把握的地方必须标出来；考号对不上、校验不通过的，绝不自动归到某个学生名下。
5. **能追溯**：每个结果都能找回对应的原图和切图。
6. **独立私有化部署**：一个单位（甚至一个院系）部署一套，一套扫描模块对接一套考研系统。部署要简单：客户端一个安装包，后台一个服务。

## 3. 整体流程

```
考研系统 ──考试信息、题目结构、学生名单──▶ 扫描模块后台
                                              │ 自动生成答题卡 → 设计 / 调整 → 下载
                                              ▼
                                   学校打印分发，学生作答
                                              │
扫描模块客户端：新建批次 → 扫描仪扫描 / 导入 PDF → 现场检查 → 当场重扫、补扫 → 逐份上传
                                              │
扫描模块后台：识别 → 切图 → 手写识别 → 校验 → 确认同步
                                              │
                                              ▼
考研系统：接收正常结果 + 异常数据 → 批改；异常卷子人工补全
```

## 4. 功能清单

### 4.1 扫描客户端（Windows 安装包）

| # | 功能 | 说明 |
|---|---|---|
| A1 | 登录与连接 | 填写服务器地址、账号登录；显示在线 / 离线状态 |
| A2 | 扫描仪设置 | 支持 TWAIN 的扫描仪都能用，不绑定品牌；设置分辨率、单面 / 双面、灰度 / 彩色 |
| A3 | 新建批次 | 选择考试；填写班级、考场（可选）；用现成卡时还要指定模板 |
| A4 | 批量扫描 | 连续扫描；实时列表显示每份卷子的学生、页数、状态 |
| A5 | 导入 PDF / 图片 | 和扫描仪并列的另一种输入方式，同样形成一个批次 |
| A6 | 现场检查与当场处理 | 当场报出缺页、混卡、空白页、扫糊、考号读不出、二维码读不出等问题；当场重扫或补扫，在客户端里合并好再提交 |
| A7 | 单张扫描 | 学生自己扫一张卡，作为一个批次；校验通过后自动同步 |
| A8 | 版式同步 | 从后台拉取答题卡版式和模板；断网时用本地缓存，照常扫描和检查 |
| A9 | 上传队列 | 卷子逐份上传到后台；断网时先存在本地，网络恢复后自动补传，不丢不重 |
| A10 | 批次汇总与确认提交 | 显示这批多少份正常、多少份异常；老师核对后点"确认提交" |

### 4.2 扫描模块后台（Web）

| # | 功能 | 说明 |
|---|---|---|
| B1 | 登录与账号、客户端管理 | 身份认证；管理哪些客户端可以接入 |
| B2 | 考试与名单 | 查看考研系统同步过来的考试、题目结构、学生名单（只读） |
| B3 | 答题卡生成 | 收到考研系统的考试和题目信息后，解析题目（多少道选择题、几个选项、主观题作答量等），自动生成答题卡。分两种：批量母版（考号由学生手填）；单份（考试 ID、学号预印在卡上） |
| B4 | 答题卡设计器 | 设计新的答题卡样式；调整已生成的答题卡（换样式、改作答框大小、调整选择题分栏、修改版头文字等）。定位标、二维码、考号区等识别必需的元素由系统自动放置，不能删除；调整后版面坐标自动更新；有批次开始扫描后锁定，不能再改 |
| B5 | 现成卡模板 | 导入现成的空白答题卡，在设计器里把各区域对应到题号；可以用样卡试识别 |
| B6 | 答题卡预览与下载 | 预览；下载批量母版、单份卡，或打包成 ZIP 下载 |
| B7 | 批次与卷子详情 | 每个批次的进度和状态；单份卷子的原图、每题切图、选择题答案、手写识别文本、异常标记 |
| B8 | 汇总与同步 | 按批次或整场考试查看应到、实收、异常的数量；校验通过后确认同步；查看同步记录，失败的自动重试，也可以手动重推 |
| B9 | 系统设置 | 识别阈值；考研系统对接地址和密钥 |

### 4.3 识别处理（后台服务，结果在 B7 中查看）

1. 页面校正（纠偏、旋转、透视）；
2. 读取二维码，匹配版式；
3. 识别考号：手写和填涂两种方式都读，两者一致才算识别成功；
4. 交叉校验：考号是否在名单里，考试 ID 是否和二维码登记的考试一致；
5. 按学生分卷，页序重排（一个 PDF 里混有多个学生的卷子也要能分开）；
6. 按题切图（一题跨页作答时输出多张切图，按顺序编号）；
7. 选择题识别：单选、多选，区分没涂、多涂、拿不准；
8. 空白题判断；
9. 手写识别：填空、作文、解答题内容识别成文字，支持中文、英文、数学公式；
10. 打包结果。

### 4.4 和考研系统的接口

| 方向 | 内容 |
|---|---|
| 考研系统 → 扫描模块 | 考试信息和题目结构，用来触发生成答题卡 |
| 考研系统 → 扫描模块 | 按考试提供学生名单，用来校验考号 |
| 扫描模块 → 考研系统 | 按批次或整场考试同步结果包：每份卷子带考试 ID、学号、批次号、批次内顺序号、每题答案和切图；异常卷子带整页原图和异常原因 |
| 考研系统 → 扫描模块 | 按考试、批次或单份卷子重新拉取结果 |

## 5. 关键规则

### 5.1 怎么确定是哪场考试

- 二维码登记了考试、卡上也有考试 ID（手填或预印）：两者必须一致，不一致进异常；
- 只有其中一样：按有的那一样确定；
- 现成卡（没有二维码）：开扫前由人工在客户端指定考试和模板。

### 5.2 同步条件

一个批次（或整场考试）满足以下条件，才允许同步：

- 每份卷子的考试 ID 在考研系统中存在；
- 每份卷子的学号在这场考试的学生名单里；
- 版式和考试一致；
- 手写识别已全部完成；
- 现场解决不了的卷子已单独标为异常数据，随这一批一起同步。

### 5.3 触发方式

| 场景 | 怎么触发同步 |
|---|---|
| 学生单张扫描 | 校验通过后自动同步 |
| 学校批量扫描 | 校验通过后，现场老师在客户端确认提交这一批 |
| 整场考试 | 管理员在后台核对整场汇总后确认同步 |

批次同步和整场同步可以混用：已经同步过的卷子不会重复发送。

### 5.4 异常数据

- 现场能处理的（缺页、扫糊、混卡等），在客户端当场处理，不进入异常数据；
- 提交后才发现、现场处理不了的（考号读不出或对不上、二维码损坏、版面认不出、事后发现缺页等），作为异常数据同步给考研系统；
- 异常卷子带批次号和批次内顺序号，考研系统可以根据前后卷子是谁判断班级、考场，缩小指认范围；
- 异常一律由考研系统人工补全，不再回到扫描模块重新识别。

### 5.5 重复与重新同步

- 每份卷子有唯一编号，重复同步时考研系统按"已存在"处理，不重复入库；
- 扫描模块后台保留全部批次、结果、原图和切图，考研系统可以随时重新拉取；
- 重新同步拿到的是同一份数据，不会重新识别或修改结果。

## 6. 质量要求

| 项目 | 要求 |
|---|---|
| 选择题识别 | 规范填涂时正确率 ≥ 99.9% |
| 考号与学生对应 | 识别不全或校验不通过必须标出来；自动归属错误为 0 |
| 按题切图 | 切图完整包含该题作答，不混入其他题内容 |
| 手写识别 | 按样卡实测，在验收方案里约定 |
| 现场问题检出 | 缺页、混卡、空白页 100% 检出 |
| 稳定性 | 一批几千张、几台客户端同时用都要稳定；断网恢复后不丢不重 |

## 7. 考研系统需要配合的

- 提供考试信息、题目结构、学生名单的接口；
- 接收扫描模块同步的结果包；
- 新增异常卷子的人工补全功能（根据整页原图、批次位置判断学生并补录）。
