## 独立审查及修复

第一次独立审查请求遇到服务 503，随后重新发起并完成。审查报告的四项均先用失败测试复现，再修复：

1. **成功重扫后旧页被恢复成新学生。** 去重原先只看当前条目和新尝试，漏了 `previous/manifest.json`。现在读取该尝试对应原序号的归档身份，重开不会重复计人。
2. **原目录删了一半时回滚不完整。** 原逻辑把“目录还存在”等同于“旧证据完整”。现在从完整备份恢复目录；对字节一致的文件避免无意义重写，仍支持目的目录持续写入失败时保留原文件。
3. **一个坏历史日志阻断整个批次。** 增加日志结构、阶段、路径与所属序号校验。坏日志保存为 `journal.corrupt-*.json`，记录恢复警告；无法确认的当前答卷标为待核对，文件保留。后续已成功替换的新尝试不会被旧损坏日志反复撤回。
4. **后台 OCR 进度漏掉重试完成。** 不再直接丢弃刷新，等待旧后台队列完成最后一次通知后再按当前文件状态补刷。

另补齐集成边界：输入源在创建迭代器时直接抛错也能被传回，避免流水线空等；阈值重判不重写正在被 OCR 读取的既有图片；持续存储故障留下未恢复的提交事务时，拒绝叠加另一轮重扫，要求先重开批次恢复。命令行重试的最终进度也按全部已保存项汇总，不覆盖成仅本次重试数。

## 使用和存储约定

- 缺面答卷采用“结束本轮 → 按原序号整份重扫 → 继续其余答卷”。本包没有加入猜测式自动补面。
- `acquisition/`、`attempts/` 是恢复及历史证据的一部分，不自动清理。保留它们会增加磁盘占用；存储不足仍应明确报错，不能据此承诺无限连续扫描。
- OCR 取消会撤销回写资格，不等于已经发出的 HTTP 请求被立即终止；迟到响应不会覆盖新结果。
- 内存队列中不再积压整页图像；这不等于已完成 600 DPI 彩色、千张、各类驱动的峰值内存/吞吐量测试。
- 历史数据损坏时保留文件并标明问题，不把无法确认的状态当作正常输出。
