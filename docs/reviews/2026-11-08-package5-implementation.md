# 第 5 组：识别质量与图片证据一致性

日期：2026-11-08。

结论：本轮实现、独立复核修正和自动回归已完成。真实设备及真实材料验收
仍按本文第 4 节单独处理，不能据此宣布整个系统已经完成现场交付验收。

本轮承接主线验收报告 RC-02、RC-03、RC-04，并修正缺考未知状态的显示。
目标仍是“扫描仪 / 图片 / 填写 PDF → 学生与答案识别 → 每题图片 →
JSON 加图片目录”。保持已有架构、纸型坐标模型和原模拟数据生成方式；
没有加入评分、ZIP、业务接口，也没有打包或提交代码。

## 1. 本轮实现

### 1.1 无效采样不再当作空白

以前 `cell_fill` 在部分越界、空数组或数组形状不一致时返回 0。
另外，纠偏整页图会将原图缺失处填成白色，仅检查数组范围无法发现这类缺失。

现在：

- 同时检查底图和扫描图的完整采样边界，防止 NumPy 静默截短切片。
- 与图像使用同一单应矩阵生成原图覆盖掩码；补白区域不算有效纸面。
- 保存每格无效原因；无效值内部为 NaN，state/result 写成 JSON `null`。
- 有无效选项的题不能确定为某个答案；缺考无效时 `value=null`，显示“未确定”。
- 考号、自定义填涂字段、选做组使用同一失败规则；无效值不进入阈值拟合。
- 重新判定前检查采样维度。缺选项、缺题行、缺整块或多出选项不能静默成为
  确定答案，也不能使题目从输出消失。

依据：`engine/omr.py`、`engine/recognize.py`、`engine/state.py`。

### 1.2 整批浅涂诊断独立于阈值拟合

原逻辑要求至少 5 个涂黑度达到 0.5 的选项才会诊断，因此一整批 0.4 左右
的浅涂可能没有提示。现在诊断不再依赖这一条件，仍要求足够的有效样本和
高于诊断噪声下限的分组；全白、弱噪声和孤立污点不会直接算作整批浅涂。

自适应阈值的原有保守拟合条件保持不变，本轮没有为了降低异常数量而放宽
答案判定或原 200 张回归的准确率要求。

依据：`threshold_issues`、`fit_thresholds`，及 `tests/test_omr.py`。

### 1.3 条码保留候选、位置与歧义

原图与 Otsu 检测结果合并；同文本在不同物理位置出现时分别保留。
字段关联仍按原区域、外扩 10 mm、必要时整页搜索进行，但所有字段一起处理
物理位置归属，避免按模板顺序抢占候选。

- 按原区域、外扩、全页证据依次关联；较弱候选不抢占已有明确归属。
- 多个直接候选、全页最近候选距离接近、同层级多个字段争用同一码，标为 `ambiguous`。
- 候选含解码值、码制、面、四角、多边形外接框、距离和找到方式。
- 保留原模板区域图片，另外输出每个候选的实际位置图片。
- `selected_id`、`hit_image` 仅指向无歧义采用的候选。
- 考号和条码仍是两个独立识别结果；不一致继续产生 `ID_MISMATCH`。
- 结果查看支持候选图，交付清单包括候选图并检查采用结果是否一致。

依据：`engine/barcode.py`、`engine/barcode_regions.py`、`output/evidence.py`、
`output/audit.py`、`ui/widgets/evidence_preview.py`。

### 1.4 识别、裁图和叠层共用有效位置

局部匹配得到的实际位移保存到 state，并进入结果中的 `sampling.shift_mm`。
客观题裁图、考号裁图、自定义填涂字段裁图和页面叠层使用该位移。
客观题保留 `template_rect`，而 `rect` 明确表示实际裁图位置。

交付检查既校验模板原矩形，也校验有限、合理范围内的位移及位移后的矩形，
不会简单把所有偏离模板的位置都放行。

依据：`engine/result.py`、`app/results.py`、`output/audit.py`。

### 1.5 保留背面浅色笔迹，兼容旧证据

新识别使用证据版本 2，背面题图不再将灰度大于 185 的像素自动抹白。
测试中灰度为 210 的整块笔迹保持不变。结果记录插值方式、背面处理策略和
原图所处处理阶段。

没有版本字段的旧 state 按版本 1 读取，保留原坐标和背面处理规则。
重新结算不改写已有图片，避免改变正在转写的证据；新增测试通过真实旧版
state、旧式图片及一个等待回写的模拟 OCR 请求验证这一点。

注意：输出仍为灰度 JPEG，仍经过几何插值；软件颜色滤除或设备处理前的
彩色原件不因此恢复。原始 PDF 保留机制仍沿用第 1 组。

## 2. 独立复核后的修正

独立代码复核发现并补齐三项：

1. 采样行长度与模板不一致时可能给出确定答案：判定前做完整维度检查。
2. 新版结果删除候选/采样章节后仍可能通过交付：版本 2 必须具备相应证据。
3. 列表等异常候选 ID 导致检查器崩溃：非法 ID 记录阻塞项，不进入采用关联。

补测先复现 11 项失败，修正后的相关测试合计 160 项通过。没有仅凭静态
推断就把这三项写为已修复。

实际 8K 样卡核对又发现：试卷条码为空时，回退全页候选会错误地与区域内
命中的学生条码争用。补充 3 个失败用例，加入位置证据优先级，使明确的
区域命中保留，缺失字段仅从剩余候选关联；同层级争用仍明确标为歧义。

## 4. 验证边界

- 200 张回归沿用 `guanzong199`，纸型是 **8K，390 × 270 mm**，不是 A3。
- 本轮未重新执行所有 A3 及以下纸型矩阵；保留前几组的尺寸支持与测试，
  不把本轮 8K 回归冒充全部纸型真实设备验证。
- 没有连接真实扫描仪，没有执行 Windows 驱动、单双面走纸和现场恢复测试。
- OCR 回写验证使用受控客户端，没有调用付费 OCR，也不代表手写转写准确率。
- zxing 解码器自身可能把紧密纵向堆叠的相同 Code128 视为一个符号。
  本轮保证保留解码器实际返回的不同位置，不能声称能拆开所有此类图像。
- 保留浅灰笔迹不代表所有浅涂、彩色笔、污损、折痕和透印都已通过实物验收。
- `failed` / `ambiguous` 及其他识别警告仍需要操作员核对，交付检查通过不等于
  答案已经人工确认。新能力主要防止把“不知道”写成“确定”并丢掉证据。
