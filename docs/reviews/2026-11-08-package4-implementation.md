# 工作包 4：批次结算与交付完整性

## 结论

本包完成了“识别结算 → 证据完整性检查 → 固定 JSON＋图片目录”的软件流程。1232 项快速回归通过，原有 200 份模拟答卷回归通过，实际界面流程生成了可读取、可检查的交付样例。

结论限定于源码和模拟验收：没有运行真实 Windows 扫描仪、真实付费 OCR，也没有提交、推送或重新生成安装包。A3 及以下、包括 390×270 mm 的 8K 支持目标不变，不能把这次验证当成所有真实纸幅和驱动均已验收。

设计依据：

- `docs/superpowers/specs/2026-11-08-delivery-readiness-design.md`
- `docs/superpowers/plans/2026-11-08-delivery-readiness.md`
- 前三包已实现的文档输入、逐题图片、模板快照、采集与重扫恢复、OCR 任务身份。

## 实现结果

| 环节 | 当前行为 |
| --- | --- |
| 结算检查 | 后台重新检查未处置答卷；空批次、processing、物理异常或任一重判失败都不能标记完成 |
| 重判恢复 | 保留失败序号和原因，可再次结算；成功项仍完成处理；已完成工作批次提供“重新结算” |
| 版本约束 | 批次有效数据变化增加 revision；过期结算既不能标记新数据完成，也不能覆盖更新的结算结果 |
| 完整判定 | 考号逐位、自定义填涂细节、一致性、缺考、选做、识别警告等变化均被写回 |
| 证据升级 | 老结果补齐逐题元数据和缺图，保留已有图像、OCR 内容及任务身份；等待中的旧路径 OCR 会按新证据重新投递 |
| 目录搬移 | 新 state 原图路径相对批次；旧 POSIX/Windows/UNC 绝对路径只映射到当前批次 raw，不回读旧位置 |
| 引用归属 | 重判写入、结果浏览和恢复均校验所属批次/答卷；不能用损坏引用读写其他答卷或目录外 JSON/图片 |
| 完整性检查 | 核对模板快照、底图、批次/学生/题目身份、所有题目及区域、字段/多条码图片、整页/原图、PDF 摘要与页码 |
| 图像检查 | 文件必须可读取、图片可完整解码；区域图片除引用一致外，还须属于对应题/区域的规范证据路径 |
| OCR 状态 | 明确 none 可交付，pending 阻止，failed 带清单交付；缺失状态不能冒充未启用 |
| 异常处置 | 作废项显式排除并保留记录；现有异常证据随附，旧作废证据缺失形成说明 |
| 固定目录 | 检查清单驱动复制、摘要对照、源变化检测、副本复查，再无覆盖发布；失败不发布半成品 |
| 只读保护 | 固定副本不可重新作为批次继续处理，不能通过 OCR 入口回写；其内部也不能创建新考试/批次 |
| 结果核对 | 共用按需读取的图片/JSON 查看器，覆盖每题、每区域及任意身份字段；坏图、换对象时清空旧画面 |
| 警告筛选 | 仅 OCR 失败的答卷也进入“有警告”；不把转写失败混入原有 OMR 警告计数 |
| 设置 | 完整校验与写盘成功后才更新有效配置；就绪时立即采用新扫描默认值，运行时延后到本轮结束 |

主线输出仍是 JSON 和图片目录，没有加入评分、ZIP、业务上传或新的数据库。

## 交付入口

图形界面：结果页“检查交付”“生成交付目录…”。

```sh
scan-answer check --batch /path/to/working-batch
scan-answer deliver --batch /path/to/working-batch --out /path/to/new-delivery
```

检查只读，失败返回非零；生成必须使用新目标目录。`recognize` 有未处置异常或重判失败时也返回非零，并保留工作目录。

固定目录包括当前 manifest、模板、结果 JSON、引用图片/原图/PDF 和已作废证据，不复制 `state/`、`acquisition/`、`attempts/`。原工作目录保留恢复材料。副本中的 `delivery.json` 记录摘要清单、警告和排除项，manifest 标明封存版本；副本可独立搬移、读取和检查。

## 审查与修复证据

独立审查的四个问题均已复现并修复：

1. **同步交换 images 与 regions.image 可以骗过一致性检查。** 改为把每项证据绑定到对应题号、小题和区域的规范路径；不仅检查内部引用互相相等。
2. **旧结算可以覆盖新一轮答卷的失效标记。** 引入批次修订约束，应用逐份结果和最后完成状态前都核对版本；已有更新结算时保留更新状态。
3. **缺少 OCR 状态被默认成 none。** 主观题和文字字段必须显式声明有效状态，缺失或非法值阻止交付。
4. **发布前最后一次 exists 检查存在覆盖竞态。** 使用系统无替换发布语义，真实并发发布测试验证只能有一个获胜者，已有空目录、文件、悬空链接均不被替换。

集成时另补了跨答卷 state/result/crop 引用保护、结果列表及恢复入口的 JSON 边界、旧证据升级后的 OCR 续接、设置保存失败回滚。

发布实现的 macOS 常量及语义通过本机 SDK 的 `sys/stdio.h`、`rename.2` 核对，并运行了原生并发用例。网络文档请求当时不可用。Windows/Linux 分支没有在本轮分别运行，不据此声称跨平台现场验证完成；不支持所需发布语义的系统/文件系统会报错。

## 实际流程与截图

使用既有生成器的 12 份模拟答卷执行：

1. 导入并识别，保留一份预设物理异常。
2. 显式作废异常，重新结算。
3. 在结果页检查完整性并查看客观题、条码等证据。
4. 生成固定目录，再对副本执行完整性检查。
5. 在结果页读取副本，确认 OCR 重试和再次生成按钮禁用。

## 验收边界及后续

- 完整性通过不代表每个识别值均正确或已人工确认。识别警告、身份存疑和 OCR 失败会随目录保留，需要业务或操作员明确核对。
- 检查器不自动删除或覆盖坏证据。缺图可重新结算补建；坏原图、坏模板等仍需恢复、重新采集或重建工作批次。
- 固定目录是应用工作流层面的封存，摘要用于发现意外修改，不是数字签名或不可移除的文件权限控制。
- 原主线分析报告中的多条码候选/定位证据、无效采样与浅涂诊断等识别算法项仍需逐项复核；本包未修改这些算法，不能据此宣称原报告全部问题已关闭。
- 还需真实 A3、8K 及更小纸幅样卡、Windows TWAIN 驱动、单双面/卡纸/停止恢复、真实 OCR 效果、600 DPI/千张性能和分发包验收。
- 未重建 `.app` 或 Windows 安装包；当前已安装程序不会自动获得本轮源码改动。

下一步应复核剩余识别质量与诊断问题，结合真实样卡和设备进行端到端验收，再做性能和安装包验证；评分和业务接口仍不作为当前扩展方向。
