## 1. 验收结论

**当前工程已经具备主体模块，但还不能按用户最新确认的完整主线给出“验收通过”结论。**

原因不只是“测试还没跑”，而是代码中存在以下三种不同情况：

1. **目标功能确实缺少。** 已填写答卷 PDF 没有接入正式识别和试识别；正常客观题没有独立裁图。
2. **入口和模块存在，但流程没有闭环。** 包括从零制作跨面模板、修改后重新确认试识别、扫描停止时保全已采集页面、重扫替换、异常恢复、OCR 重试以及批次完成。
3. **已有代码，尚无本轮运行证据。** 包括实际扫描仪、跨版式识别精度、真实手写 OCR、吞吐量、内存和最终安装包。

不建议推倒重写。现有 Python、PySide6、模板数据层、图像源、流水线、识别引擎、本地输出和 OCR 分层可以保留。应围绕“学生、题目、答案、图片、来源一一对应”补齐主线，再做实际验收。

本报告是对[设计与实现一致性报告](/Users/liuyuhua/github/scan-answer/docs/reviews/2026-11-08-design-implementation-consistency.md)的业务优先级重排和补充。前一份偏重架构一致性；本份以能否完成用户的实际工作为准。

## 2. 本次采用的产品范围

### 2.1 核心目标

```text
扫描仪 / 已填写图片 / 已填写 PDF
    -> 建立考试并选择确定的模板
    -> 页面归属与正反面配对
    -> 定位、纠偏、提取学生信息与答案
    -> 每道题对应的作答区域图片
    -> 可选手写 OCR
    -> 异常处理、重扫、恢复、完成确认
    -> 可独立读取的 JSON + 图片目录
```

模板制作、考试/试卷配置、扫描管理、试识别、设置和结果查看，都是这条主线的必要支撑，不属于边角功能。

### 2.2 三个必须说清的范围界限

- **“识别题目”按当前设计是按模板识别题号、题型和作答区域。** 不是从任意无模板试卷自动理解题干、自动分题或建立题库。后者没有进入本次必做清单。
- **“答案”不等于“判分”。** 客观题输出实际填涂及状态；主观题先有图片，配置 OCR 后再有转写文字。OCR 未启用时保留图片、明确标记未启用，是允许的正常结果。
- **“每题有图片”允许一题多张有序区域图。** 跨面、跨区域题不必强制合成长图，但 JSON 必须表达它们属于同一道题及顺序。

### 2.3 与早期设计相比，新明确的验收口径

早期正式设计只明确把 PDF 接入空白模板导入，并在识别输入侧写图片导入；客观题图片也只要求异常题裁图。见[总体设计第 85 行](/Users/liuyuhua/github/scan-answer/docs/superpowers/specs/2026-11-06-scan-answer-design.md:85)、[第 185 行](/Users/liuyuhua/github/scan-answer/docs/superpowers/specs/2026-11-06-scan-answer-design.md:185)。

用户现在明确提出“扫描仪、图片或 PDF 输入”和“每个题对应图片”。因此，PDF 答卷输入和全量逐题裁图是当前必须补齐的范围；不能一边沿用旧实现，一边宣称已经满足新口径，也不应把这两项简单归责为原实现违反旧计划。

### 2.4 当前不作为阻塞项

评分、阅卷、成绩统计、名单比对、人工改答案、业务系统 HTTP 对接、对象存储、ZIP 打包、可插拔导出框架、macOS 原生扫描仪、多张物理纸组成同一学生答卷，均不作为本轮主线完成的前提。

先完成一个完整、可搬移、可核对的目录交付即可。ZIP 只是后续承载形式，不会修复目录内部缺图、错图或状态不完整的问题。

### 2.5 纸张范围与已有样卡：按用户补充更正

**支持范围为 A3 及以下尺寸，包含当前这张 8K 卡，以及 A4、A5 和范围内的其他实际纸幅。** 软件按模板中的毫米尺寸和方向处理，不能只提供“A3/8K”两个硬编码分支；扫描仪能实际送入的最小纸幅由设备能力限制，应明确提示。

项目已经有真实 8K 空白卡扫描件：[samples/raw/8k-199.pdf](/Users/liuyuhua/github/scan-answer/samples/raw/8k-199.pdf)。其现有模板记录纸张为 **390×270 mm、底图 300 DPI、正反两面**，见 [template.json](/Users/liuyuhua/github/scan-answer/templates/guanzong199/template.json)和[模板生成工具第 15 行](/Users/liuyuhua/github/scan-answer/tools/build_template_199.py:15)。不能将这个样本改称 A3，也不能说项目没有 8K 样本。

用户早在原会话中已经要求利用该真实空白卡自行模拟测试。现成的生成器、已知答案与回归方法应继续复用，不需要重新建立一套测试起点，也不把新增真实填涂样本作为继续开发的前提。模拟验证与设备真机验证分开记录即可，详见第 9 节。

## 5. 缺口与整改验收条件

每项“验收条件”都是后续应执行的场景，不是本轮已通过结果。

### IN-01｜P0｜填写答卷 PDF 没有进入识别主线

**证据：** [folder.py:12](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/folder.py:12)只接受图片扩展名；[scan_page.py:255](/Users/liuyuhua/github/scan-answer/src/scan_answer/ui/pages/scan_page.py:255)只有扫描仪和图片文件夹；[trial.py:43](/Users/liuyuhua/github/scan-answer/src/scan_answer/app/trial.py:43)逐文件读图片；[auto.py:545](/Users/liuyuhua/github/scan-answer/src/scan_answer/template/auto.py:545)的 PDF 分页仅供模板导入。

**影响：** 用户提供多份学生答卷的 PDF，无法在产品内完成“选文件—分页—配卡—识别—逐题图—JSON”。把 PDF 放进图片目录会被过滤，不等于“已支持”。

**补齐：** 实现统一的文档页输入，正式识别和试识别共用。保留原文件、页码、渲染 DPI、页面归属；逐页处理，不能复用新建模板“只取前两页”的业务规则。支持页数预览和错误说明。

**验收条件：** 10 页双面 PDF 产生 5 份、每页可追溯；奇数尾页明确缺面；损坏或加密文件明确报错；多文件边界不跨文件误配；重开后没有重复处理和漏页。

### IN-02｜P1｜文件输入缺少导入清单与配组预检

**证据：** [folder.py:16](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/folder.py:16)直接筛选并按文件名排序；[folder.py:46](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/folder.py:46)只有所有文件都带 `_N` 才按前缀分组，否则全部退回顺序分组；[scan_page.py:461](/Users/liuyuhua/github/scan-answer/src/scan_answer/ui/pages/scan_page.py:461)每次启动新建文件夹源，没有已导入源清单。

**触发与影响：** 多加一个不合命名规则的文件就会改变整批配组策略；再次识别同一目录可重复分配新序号。多页 TIFF 扩展名虽可被接收，当前单图读取路径没有逐帧枚举或明确拒绝说明。后端版面匹配不能证明两面属于同一学生。

**补齐：** 开始前列出文件、页数、配组、忽略项和异常；混合命名不要静默降级；保存导入身份与已完成页，提供明确“跳过已导入/作为新输入”的选择。多页 TIFF 要展开，或明确提示不支持。

**验收条件：** 覆盖混合命名、自然序号 `1/2/10`、缺一面、重复后缀、重复导入、空目录、多页 TIFF；页面归属和忽略原因可见，不能静默丢页或重复计人。

### SC-01｜P0｜模板面数与扫描仪实际模式必须一致

**证据：** [twain_source.py:266](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/twain_source.py:266)将参数失败统一当警告；[第 274 行](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/twain_source.py:274)设置双面；[第 418 行](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/twain_source.py:418)仍按模板面数配组；[scan_page.py:554](/Users/liuyuhua/github/scan-answer/src/scan_answer/ui/pages/scan_page.py:554)未阻断单双面冲突。

**影响：** 双面模板配合单面采集，或双面能力失败后沿用驱动默认值，会使采集分组前提失效。中断的一面先记异常，整纸放回后“继续”又产生新序号，缺少替换关系。代码会清空每轮暂存，不应误称为必然跨轮拼接；风险在配组身份和恢复关联。

**闭环：** 关键能力失败应阻止启动；明确纸张、页面、学生答卷、扫描尝试四种身份。卡纸恢复选择补面、整份重扫或作废，并保留旧序号关联。

**验收条件：** 用不同学生可辨识的正反面验证单面误设、双面设置失败、正面后卡纸、双张恢复；不得输出混合学生答卷。实际出页顺序需真机确认。

### SC-02｜P0｜高分辨率采集队列无界，暂停又阻塞结果回收

**证据：** [twain_source.py:392](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/twain_source.py:392)用无界队列传整页数组；[runner.py:136](/Users/liuyuhua/github/scan-answer/src/scan_answer/pipeline/runner.py:136)只限制识别任务窗口；[control.py:49](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/control.py:49)暂停等待和结果收集处于同一消费流程。

**影响：** 采集快于识别或暂停时，整页图可能积压在内存；已经完成的 worker 结果可能尚未登记 manifest、更新界面或投递 OCR，因为主循环正在等待下一条输入。不是每次暂停都会发生，但存在明确未分离的路径。

**闭环：** 采集落盘队列、识别调度、结果收集分开；根据图像字节数设预算和高水位策略。暂停进纸/接收，不妨碍已提交任务收尾；不能只靠“workers×2”声称控制了全链路内存。

**验收条件：** 600 DPI 彩色连续输入、识别故意变慢和长时间暂停时内存受控；暂停期间既有任务仍登记完成；每个已接收页面有明确落盘或异常记录。

### SC-03｜P0｜停止本轮需要排空页面并确认设备释放

**证据：** [twain_source.py:375](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/twain_source.py:375)停止后不再取队列；[control.py:47](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/control.py:47)直接返回，未显式关闭内部迭代器；[twain_source.py:436](/Users/liuyuhua/github/scan-answer/src/scan_answer/source/twain_source.py:436)仅发关闭请求；原图到 [session.py:169](/Users/liuyuhua/github/scan-answer/src/scan_answer/pipeline/session.py:169)才落盘。

**影响：** 结束本轮时，已经进入队列或半份暂存区但尚未交给流水线的页面，存在不留原图和序号就退出的路径。停止标志也不代表设备资源已经释放，重扫可能过早接手。

**闭环：** 分离“停止进纸”“传输收尾”“页面持久化”“半份登记”“识别排空”“设备已释放”。未确认释放时不能再次占用设备；超时要明确保留占用状态。

**验收条件：** 在队列积压、只收到正面、传输中、暂停后分别停止；已接收页无遗漏，半份可恢复，设备只被一个会话持有。驱动取消时序待真机验证。

### SC-04｜P0｜重扫替换缺少事务，普通事件缺少会话身份

## 6. 必须形成的八个闭环

| 闭环 | 从哪里开始 | 什么才算结束 | 当前断点 |
|---|---|---|---|
| 输入闭环 | 选择文件/PDF或启动设备 | 每页都有来源、归属、落盘或明确失败 | PDF未接入、导入预检不足、停止页丢失路径 |
| 模板闭环 | 从空白卡新建 | 完整题目和字段可配置，当前修订试识别可核对，保存可重开 | 跨面、定位切换、引用联动、试识别过期 |
| 身份闭环 | 页面配组 | 一份物理答卷对应一个稳定ID，考号和条码独立可追溯 | 设备模式、混合命名、异常续扫关联 |
| 题图闭环 | 模板题号/区域 | 每题答案、状态、一个或多个正确题图和来源映射完整 | 正常客观题缺图、命名冲突、裁图与采样位置 |
| 异常闭环 | 卡纸/缺面/损坏/识别失败 | 明确恢复、重扫替换或作废，旧证据可追溯 | 替换先删旧图、设备释放、迟到事件 |
| OCR闭环 | 可选启用或重试 | 同一有效任务只处理一次，状态/摘要一致，旧任务不能回写 | 三类入口分裂、配置与任务代次 |
| 完成闭环 | 结束采集/批次 | 在途排空、最终判定落盘、异常处置、OCR状态明确 | 前端检查早于后台结果、部分重判仍finalized |
| 交付闭环 | 定稿输出目录 | 文件齐全、对应正确、路径可搬移、版本固定 | 没有交付前统一完整性判定 |

这八个闭环都是为了可靠完成识别，不是额外增加评分、业务系统或复杂平台。

## 7. 建议的最小交付契约

先保留现有 `result.json` 主体，不必为了架构形式重做所有字段。对以下关系给出正式定义：

| 对象 | 至少应能回答的问题 |
|---|---|
| 输入页 | 来自哪个文件/设备、PDF第几页或本轮第几面、原始文件在哪里 |
| 答卷 | 属于哪个考试/批次、稳定序号是什么、哪些页组成、当前扫描尝试是哪次 |
| 模板 | 使用哪个确定版本/内容修订，底图及坐标是否可追溯 |
| 学生身份 | 填涂、条码、手写信息分别是什么，各自状态和证据是什么 |
| 题目 | 完整题号/小题号、题型、实际答案或转写状态、对应的有序图片 |
| 图像 | 是采集图、处理图、纠偏图还是题图，来源与裁切位置是什么 |
| 异常 | 影响哪份/哪题，是否可恢复，重扫或作废如何关联 |
| OCR | 未启用、等待、执行、成功、失败、取消/过期如何表达，模型与来源如何保留 |
| 交付 | 是否仍会变化、图片是否完整、是否有已说明的失败项，最终修订是什么 |

可继续使用客观题 `image` 和主观题 `images[]`，也可在兼容旧结果的前提下统一访问方式。核心是每题对应关系，不是字段长得一样。

本地交付最少包含 manifest、各答卷结果、全部被引用图片和必要模板/来源信息。内部 `state/`、临时锁文件是否交付可另定，但不能让对外 JSON 依赖未包含的资源。

建议设定以下不变量：

1. 已接收输入页均能在清单中找到，无静默丢页。
2. 一份答卷的页面不跨学生；同一原始输入重复导入有明确处理。
3. 每个逻辑题目都有答案状态和图片结果，缺图不能默认为完成。
4. 图片路径唯一、存在、可解析且在规定交付范围内。
5. 识别失败不能被转换成正常空白或“未缺考”等确定业务值。
6. 过期 OCR、过期试识别、旧批次事件不改变当前有效结果。
7. 重扫有尝试历史或至少可回滚，不先毁掉唯一旧证据。
8. 批次完成与交付就绪依据后台持久化状态，不能只依据按钮或界面计数。
