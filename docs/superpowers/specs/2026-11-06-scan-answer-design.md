## 1. 目标与范围

### 1.1 要做什么
一个桌面软件：通过 USB 连接高速双面扫描仪，批量扫描答题卡，按模板识别出考生信息、每道客观题的答案、主观题切图（可选手写转写），按统一 JSON 结构加图片文件输出。**不做批改、不做阅卷。**

### 1.2 设计原则
1. **扫描端只负责采集和识别，不做业务判断。** 能识别的都原样写进 JSON；冲突和异常只标记、不裁决，交给业务系统处理。
2. **物理异常在现场处理，数据异常只做标记。** 纸还在扫描员手上时能补救的问题，比如定位失败、双张、缺页，要求现场重扫或作废；其余问题都只写进 JSON。
3. **不静默出错。** 识别没有把握的地方必须标出状态（`uncertain` 等），不能给出一个看似正常的错误值。
4. **核心逻辑与界面、扫描仪解耦。** 识别引擎是纯函数（输入图像和模板，输出结果），在 macOS 上用图片就能完整开发和测试。

### 1.3 第一期范围

| 包含 | 不包含（后期） |
|---|---|
| Windows 上通过 TWAIN 连接扫描仪；macOS 和 Windows 都支持导入图片 | macOS 扫描仪接入（ImageCaptureCore） |
| 可视化制作模板（以空白卡为底图） | 从制卡系统导入坐标 |
| 一个学生一张纸（双面）；数据结构预留多张 | 一个学生多张纸 |
| OMR：考号、客观题、缺考、自定义填涂字段、选做标记 | 人工校对、修改识别结果（字段已预留） |
| 一维码、二维码识别 | 导入考生名单做比对 |
| 主观题、信息栏切图；可选的大模型手写转写 | zip 打包、HTTP 推送、对象存储上传（导出器接口已预留） |
| 本地目录输出 JSON 和图片 | |

| 项 | 选择 | 说明 |

## 3. 架构

```
┌──────────────────────── UI 层 (PySide6) ────────────────────────┐
│  考试  扫描  模板编辑器  结果浏览  设置                          │
└───────────────┬───────────────────────────────▲─────────────────┘
                │ 命令                          │ Qt 信号(进度/结果/异常)
┌───────────────▼───────────── pipeline ────────┴─────────────────┐
│ 图像源 ─▶ 正反面配对 ─▶ 识别进程池 ─▶ 结果写出 ─▶ OCR 队列(可选) │
└──┬────────────────────────┬──────────────────┬──────────┬───────┘
 source/                 engine/            output/      ocr/
 TwainSource(Win)        预处理/定位/方向     本地目录导出器  OpenAI 兼容
 FolderSource            OMR/条码/切图       (预留导出器)    异步、重试
                               ▲
                         template/ 模板模型 + 存储
```

| 模块 | 职责 | 依赖 |
|---|---|---|
| `source/` | 统一的图像源接口：按顺序产出页面图像，并上报设备事件（卡纸、双张、缺纸）。`TwainSource` 连接扫描仪；`FolderSource` 导入图片，按文件名排序后两两配对 | 只有 `TwainSource` 依赖 Windows |
| `template/` | 模板数据模型、JSON 读写、版本号 | 无 |
| `engine/` | 纯函数：`recognize(front_img, back_img, template) -> SheetResult` | OpenCV、zxing-cpp |
| `pipeline/` | 编排：扫描线程和识别进程池并行；计数、批次状态、重扫接续 | engine、source、output |
| `output/` | 导出器接口；第一期只实现本地目录导出器。写文件时先写临时文件再改名（原子替换） | 无 |
| `ocr/` | 后台队列：读取切图、调用大模型、回写 `result.json`；支持并发数、超时和重试 | HTTP 客户端 |
| `ui/` | 五个页面；只调用 pipeline 和 template 的接口，不包含识别逻辑 | PySide6 |

**性能目标**：识别吞吐量要高于扫描速度。按每分钟 100 张纸（200 面）估算，单面识别耗时 0.1–0.3 s，开 4 个识别进程就足够。界面只接收缩小后的预览图；原图的读写和缩放都在后台完成。600 DPI 时要限制并发数，控制内存占用。

## 4. 模板

### 4.1 制作流程
1. **导入底图**：扫描空白卡的正反面，或者导入 PDF/图片。底图统一换算为 **300 DPI**，坐标单位为 mm（相对于纠偏后的底图）。
2. **设置每一面的定位方式**（见 4.3），系统自动检测，用户在画布上确认或修正。
3. **框选区域、填写参数**（见 4.2）。客观题块只需框出整块并填写题数、选项数和方向，系统先按网格生成选项框，再**自动吸附**到底图上实际的印刷框；个别没吸附准的可以手动拖动。
4. **试识别**：导入 3–5 张已填涂的样卡（第一期用模拟样卡），把识别结果叠加在画布上，全部正确后再保存。
5. **保存**：模板带版本号；每次扫描批次都在输出目录里保存一份模板快照。

### 4.2 区域类型

| 类型 | 参数 | 识别方式 |
|---|---|---|
| 定位块 | 四角（可多于 4 个） | 全局对齐 |
| 定位外框 | 一个或多个大矩形框 | 全局对齐（用于没有定位块的面） |
| 同步头 | 方向（横或竖）、个数 | 辅助定位，用于行对齐 |
| 考号填涂 | 位数、每位候选值（0–9）、排列方向 | OMR |
| 自定义填涂字段 | 字段名、位数、候选值（数字/字母/自定义） | OMR（考场号、座位号、科目、AB 卷等） |
| 条码 / 二维码 | 字段名、码制（可自动） | 条码识别 |
| 缺考标记 | 单个填涂框 | OMR |
| 信息栏 | 字段名、标签 | 切图，可选转写 |
| 客观题块 | 起始题号、题数、选项数（2–8）、选项标签、方向、类型（单选/多选/判断）、每组题数 | OMR |
| 主观题 | 题号、小题号、题型（填空/问答/作文）、内容类型（中文/英文/数学）、**一个或多个区域（可以跨面），并指定拼接顺序** | 切图，可选转写 |
| 选做组 | 关联的题号组、选做标记框 | OMR |
| 忽略区 | 无 | 不处理 |

### 4.3 每一面的定位方式
- **定位块**：找四角黑块，然后做透视校正。199 卡的正面用这种方式。
- **外框**：在二值化图上找面积最大的几个四边形轮廓，用它们的角点做透视校正。199 卡的**背面没有定位块，用这种方式**。
  - 已用真实背面验证：原图倾斜 +1.27°，能识别出来并纠正。
  - 模拟 ±3° 旋转、±8 mm 平移、±2% 缩放共 20 次，**全部成功，最大对齐误差 0.27 mm**。
- **特征匹配**：和空白底图做特征点匹配（ORB + ECC 精配准），作为兜底方案。

### 4.5 199 卡的版面实测（来自 `samples/raw/8k-199.pdf`）
- 纸张约 390 × 270 mm（大 8K），横版，中间有一条折叠线
- 正面：
  - 四角有定位块，左侧边缘有一列竖向同步头（10 个对应考号的 0–9 行，另有 2 个对应"正确涂卡/缺考"行）
  - 考生编号 15 位，每位 0–9；报考单位、考生姓名为手写栏；缺考标记
  - 选择题 1–55，选项 A–E，分 4 列，每 5 题一组
  - 考生信息条码和试题信息条码的粘贴区；写作 56 的第一部分（格子编号 100–500）；底部有"阴影部分请勿作答"区
- 背面：
  - **没有定位块**；有"考生姓名"手写栏
  - 写作 56 的续写部分（600–700）；作文 57（左下 100–200，右栏 300–800）
  - 能看到正面的**透印**
- 卡面有浅色底纹，选项括号也印得很浅，可能是滤除色印刷

## 5. 扫描与识别流程

### 5.1 扫描参数
双面、**默认 300 DPI（可选 200/300/400/600）**、默认灰度（可选彩色）、按纸张尺寸自动裁切、超声波双张检测默认开启、可选颜色滤除（红/绿/蓝），参数都通过 TWAIN 能力项设置。600 DPI 会明显降低扫描速度，存储空间约为 300 DPI 的 4 倍，界面上会有提示。

**DPI 与模板解耦**：识别时在约 200 DPI 的工作图上进行，切图从原分辨率图像上裁切。

### 5.2 每张纸的处理步骤
```
① 正反面配对   扫描仪双面输出按顺序两两配对；导入图片时按文件名排序配对
② 方向与正反面  每面分别尝试 0°/180°，用 fingerprint 匹配模板的 front/back → 自动旋转、交换
③ 全局对齐     按该面的定位方式：定位块 / 外框 → 透视校正；失败时依次兜底：
               特征匹配 → 借用正面推算（仅用于切图，标记 front_derived）→ 判为物理异常
④ 局部微调     每个客观题块、考号区在 ±15px 范围内与空白底图的对应块做匹配，修正残余偏移
⑤ OMR         逐格计算涂黑度（减去空白底图）→ 批次自适应阈值 → 同一题内选项相互比较
               → ok / blank / multiple / uncertain
⑥ 考号/条码    考号逐位做 OMR；条码先在区域内识别，失败则增强对比度后重试，再失败就全页搜索
⑦ 切图        主观题、信息栏、异常客观题从对齐后的原分辨率图上裁切；背面先去除透印
⑧ 写出        result.json + images/；若配置了大模型，把主观题投递到 OCR 队列
```

### 5.3 OMR 判定
- **涂黑度** = 选项框内的深色像素占比（先减去空白底图对应位置，扣除印刷的 `[A]` 和底纹）。
- **批次自适应阈值**：统计整个批次所有选项的涂黑度分布，分出"已涂"和"未涂"两组。分布异常（比如整批偏浅）时提示用户。
- **题内比较**：单选题取涂黑度最高的选项，并且要求它和第二名的差距足够大；差距不够就判为 `uncertain`（涂浅或擦改），超过阈值的选项不止一个就判为 `multiple`。多选题输出所有超过阈值的选项。
- 每个选项的原始涂黑度都写进 JSON 的 `fill` 字段。

### 5.4 异常分类

| 类别 | 例子 | 处理 |
|---|---|---|
| **物理异常**（现场处理） | 找不到定位点或外框，所有兜底都失败；正反面都匹配不上模板；扫描仪报双张或卡纸；图像数为奇数（缺一面）；接近全白（空白页）；歪斜超过上限 | 不生成学生结果，放入 `errors/`；界面"待处理"列表实时显示；扫描员可选择**重扫**（沿用原序号）或**作废** |
| **数据异常**（只做标记） | 选项 `blank` / `multiple` / `uncertain`、考号某一位识别失败、条码与考号不一致、缺考已涂、OCR 失败、使用了兜底定位方式 | 正常输出，写入对应字段的状态和顶层的 `warnings` |

**卡纸或双张导致停机后的接续**：两种方式都支持。
- 停机时：把问题卡放回进纸口最前面，点"继续"，按原顺序接着扫（默认）。
- 扫完后：在"待处理"列表里集中重扫。

### 6.3 manifest.json
批次信息、考试元信息、模板快照路径、计数（总张数、成功数、物理异常数、各类数据异常数）、批次阈值、OCR 进度，以及学生索引（`seq`、目录、考号、`warnings` 数量）。

## 7. 手写转写（可选）
- 没有配置大模型时：主观题只切图，`ocr_status: "none"`，整个流程不需要联网。
- 配置后：识别完成的主观题切图进入后台队列；并发数、超时、重试次数可配置；转写结果原子回写 `result.json`；失败标记为 `failed`，可以手动重试。
- 提示词按题目的内容类型切换：中文作文、英语、数学（输出 LaTeX）。
- 扫描速度不受转写影响。

## 8. 界面

以正式稿为准（`design-demos/答题卡扫描识别-正式稿.html`）。整体是浅色主题，区域色码贯穿所有页面：考号蓝、客观题绿、主观题橙、条码紫、定位黑、物理异常红、数据警告琥珀。

| 页面 | 要点 |
|---|---|
| 考试 | 考试列表（构成条）、批次列表（张数、成功、物理异常、数据警告、OCR 进度、查看结果、打开目录）、新建考试表单 |
| 扫描 | 左栏：物理异常（重扫、作废）、数据警告、区域色码<br>中栏：计数、**批次拼图**（每格一张纸，每行 50 张；成功浅绿方块、警告琥珀扇形、异常红圆、识别中蓝方块、待扫空框；悬停显示原因，点击查看）、最近一张卡的预览和识别读数<br>右栏：输入源（扫描仪/导入图片）、扫描参数、暂停/继续、新批次、结束批次；空格键暂停 |
| 模板 | 左边是区域树；中间是画布（正面/背面切换、缩放、拖动、8 个手柄、方向键微调、撤销重做、框选多个）；右边是属性面板（参数、位置、吸附结果）；工具栏：自动找定位点、**自动检测外框**、区域工具、自动吸附、试识别 |
| 结果 | 学生列表（全部/有警告/异常筛选）；详情：卡面叠加识别结果、异常定位、客观题答案表（涂黑度）、主观题切图和转写文字 |
| 设置 | 扫描默认参数、大模型配置（含测试连接）、输出目录与命名、区域色码 |

PySide6 实现要点：布局用 Qt 布局管理器（不要照搬 HTML 结构）；批次拼图和开关用 `QPainter` 自绘；表格用 `QTableView` + Model；界面线程只处理缩小后的预览图；开启高 DPI 支持。

## 9. 测试策略

### 9.1 模拟测试集（自己生成，不依赖外部样本）
以 `samples/raw/8k-199.pdf` 的真实正反面为底图（300 DPI），程序化生成测试集：
- **填涂**：
  - 在真实选项框位置画铅笔质感的涂块，有深涂、正常、浅涂、擦改残留、多涂、空白几种
  - 考号逐位填涂，包括漏涂和多涂一位；缺考标记
  - 条码由 zxing-cpp 生成后贴上；也有不贴条码的样本
  - 姓名、作文用楷体字形加随机抖动，模拟手写；也有写满到边框、压到框线的样本
- **扫描扰动**：
  - 几何：旋转 ±3°、平移 ±8 mm、缩放 ±2%、轻微透视、非刚性形变（模拟纸张起伏）
  - 图像质量：模糊、噪点、亮度和对比度变化、JPEG 压缩
  - 纸张：背面透印、折角遮住定位块
  - 进纸：上下颠倒、正反面互换
  - 页面：空白页、奇数页
- **标准答案**：每张图都附带一份 `truth.json`，结构与 `result.json` 一致。

### 9.2 验收指标
| 指标 | 目标 |
|---|---|
| 客观题：正常填涂的识别准确率 | ≥ 99.9% |
| 静默错误（答案错但状态是 `ok`） | 0（浅涂、擦改必须标为 `uncertain` 或 `multiple`） |
| 考号逐位准确率（正常填涂） | ≥ 99.9%；涂错的位必须标出来 |
| 全局对齐误差（正面定位块、背面外框） | ≤ 0.5 mm |
| 物理异常识别（找不到定位、正反面不匹配、空白页、缺页） | 100% 被识别出来，不会混进成功结果 |
| 方向与正反面纠正 | 100% |
| 识别吞吐量（4 进程，300 DPI） | ≥ 200 面/分钟 |

### 9.3 分层测试
- **单元测试**：模板读写和校验、OMR 判定逻辑、正反面配对、定位兜底链、JSON 结构（用 JSON Schema 校验）、导出器的原子写入。
- **回归测试**：每次修改识别代码后跑一遍完整的模拟测试集，输出准确率报告，指标不达标就算失败。
- **OCR**：用模拟接口测试排队、重试、失败回写；真实模型只做人工抽查。
- **界面**：用 pytest-qt 做冒烟测试（能启动、能切页、模板能保存和读取）。
- **Windows 真机测试清单**：连接 fi 系列或同档 A3 扫描仪；双面连续扫描 100 张；卡纸和双张停机后接续；重扫和作废；300 DPI 与 600 DPI 的速度对比；连续扫描 1000 张时的内存曲线；颜色滤除设置是否生效。

### 9.4 已知局限
模拟数据无法完全复现真实的纸张形变、笔迹压力和扫描仪的特性。以后拿到真实填涂样本时，再加进回归测试集即可，不需要改动设计。

## 10. 决策记录

| # | 决策 | 原因 |
|---|---|---|
| 1 | 只在 Windows 上连接扫描仪；macOS 和 Windows 都能运行（macOS 只能导入图片） | 高速扫描仪的 TWAIN 生态在 Windows；开发在 Mac 上进行 |
| 2 | 桌面软件，推送功能后期再做 | 先跑通本地采集和识别 |
| 3 | 在软件里可视化制作模板，以空白卡为底图 | 不同考试的卡不一样 |
| 4 | 题型自由组合，主观题支持多个区域、跨面 | 199 卡的写作 56、作文 57 都跨区域 |
| 5 | 手写转写可选，只接 OpenAI 兼容接口 | 不配置也能用，配置后效果最好 |
| 6 | 图片存为独立文件，JSON 里写相对路径 | 文件小，方便查看和处理 |
| 7 | 填涂考号和条码都识别、全部输出，不做裁决；第一期不导入名单 | 扫描端不做业务判断 |
| 8 | 现场只处理物理异常，识别结果不能手动修改 | 同上；`manual` 字段已预留 |
| 9 | 一个学生一张纸，数据结构预留多张 | 实际考试基本都是一张 |
| 10 | 使用 PySide6 | 用户选择 |
| 11 | 默认 300 DPI，最高 600 DPI | 用户要求 |
| 12 | 每一面单独配置定位方式，背面用外框定位，并设置兜底链 | 这批卡的背面没有定位块，而且是歪的；已用真实背面验证 |
| 13 | 测试数据以真实空白卡为底图模拟生成 | 用户要求，不依赖外部样本 |
| 14 | 界面采用方向 1（区域色码）+ 方向 3 的批次拼图 | 用户确认正式稿 |
