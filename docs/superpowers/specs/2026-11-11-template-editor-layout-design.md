# 模板编辑页按功能区重排（方向 C）设计

## 为什么

用户反馈模板编辑页的操作按钮“散落在各处，不知道怎么用”：两行工具栏里定位、画框、吸附、试识别、旋转、视图、撤销混在一起，同一类功能被拆在两行，看不出先后。目标是按功能区分组，让新手一眼知道每块区域管什么。

## 目标 / 非目标 / 反目标

- 目标：按“导航与保存 / 画框工具 / 视图 / 自动处理 / 区域属性”分区摆放；原有功能、快捷键、悬停说明、“?”说明一个不少。
- 非目标：不改识别、吸附、试识别等功能本身的行为；不改配色体系；不加分步向导。
- 反目标：任何现有功能找不到了、或只能通过更多点击才能用到（画框反而应更少点击）。

## 方案选择（Approaches）

原型在 `design-demos/toolbar/`，记录在 `design-demos/direction-approved.md`。

- A 分组工具栏：保留两行工具栏，按 ①定位 ②画区域 ③检查 分组加小标题。改动小，但仍是一长排按钮。
- B 步骤条：定位 → 画区域 → 试识别 → 保存，每步只显示本步工具。引导强，熟手要来回切步骤。
- C 工具坞（**用户选定**）：竖排画框工具 + 画布底部悬浮视图条 + 右侧“自动处理”卡片，顶栏只留导航与保存。
- 中途考虑过 A 的工具栏 + C 的竖排工具（D 版），用户看完 C 完整版（`C-完整版.html`）后定为 C。

## 布局（以 `design-demos/toolbar/C-完整版.html` 为准）

1. **顶栏（一行）**：‹ 模板列表 │ 模板名 · 改名… · 规格摘要 …… 撤销 重做 │ 试识别… ? │ 保存模板（主按钮）。
2. **左栏**：保持现状——区域标题与计数、当前面定位方式（?）、主观题目标（?）、区域树。
3. **画框工具列（新增，左栏右侧的竖列）**：顶部“选择”，然后小标题“画框 ?”（regions 说明），常用类型：考号、客观题、主观题、条码、信息栏、缺考标记；分隔线后：填涂字段、选做组、标识区、忽略区；分隔线后：定位块、定位外框。每项带区域色块和原有悬停说明（`TOOL_TIPS`），互斥选中；画完自动回到“选择”、Esc 取消的行为不变。替代原“选择”按钮和“画框：选择类型”下拉。
4. **画布底部悬浮条**：正面/背面、− 百分比 +（点百分比恢复适应窗口）、旋转底图 ▾（菜单内容不变）。
5. **右栏顶部“自动处理”**：三张卡片，每张：标题 + 一行说明 + “?” + 操作按钮。
   - 识别版面 —“运行”（原 layout_btn 行为）。
   - 自动定位 — 说明行显示当前面的定位状态（复用状态栏里定位点/外框/同步头的文字）；“重找 ▾”菜单：自动找定位点 / 自动检测外框 / 自动识别同步头（原三个按钮，悬停说明不变），“?”为 anchors 说明。
   - 自动吸附 —“运行”，“?”为 snap 说明。
   卡片下方是原属性面板。
6. **试识别时**：右栏整体切到试识别结果面板，“自动处理”卡片随属性面板一起隐藏；退出试识别后恢复。

## 已定的实现取舍（我的判断，供核对）

- 竖排工具用可勾选的 QPushButton + 互斥 QButtonGroup，对外暴露 `tool_btns: dict[kind|None, QPushButton]`；`select_btn` 保留为 `tool_btns[None]`。
- 悬浮条用 QGridLayout 把画布和悬浮条叠在同一格、底部居中，不手算位置。
- `props_stack` 第 0 页改为“自动处理卡片 + 属性面板”的容器，第 1 页仍是试识别面板。
- 依赖旧控件的测试（`tool_combo`、`props_stack.currentWidget() is page.props`）随之更新；其余控件名（`layout_btn`、`snap_btn`、`trial_btn`、`rotate_btn`、`auto_btns`、`face_seg`、`zoom_btn`、`undo_btn` 等）保留。
- 使用说明（`help_text.py`）里提到“工具栏‘画框’下拉”等位置的文案同步改为新位置。
