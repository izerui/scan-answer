# 工作包 4：批次结算与交付完整性

用户已授权继续。保留前 3 包未提交改动，共享 main 工作区，不自动提交、推送、打包。Python/PySide6 和 JSON＋图片目录继续作为主线；不增加评分、ZIP 或业务上传。

## 实现选择

区分识别结算和交付：`finalized` 表示已按最终阈值完成识别结算，只有无 processing / 未处置物理异常且全部重判成功才为 true。交付另行检查全部引用和 OCR 状态，生成新的固定目录。

只增加“已结束”标签不能证明文件完整，直接复制正在被 OCR 改写的工作目录也不能保证版本一致。本包选用独立检查器及临时目录构建后原子发布的交付目录，不引入数据库或新打包格式。

## 结算与恢复

- 排空采集后在后台重新检查，界面提前检查不作为唯一依据。
- 重判失败记录序号和原因，保留可重试状态，不调用成功的 mark_finalized。仍可对其余成功项完成重判。
- 比较完整判定，包括考号逐位、填涂字段细节、一致性、缺考、选择组与识别警告；保留 OCR 代次与结果，不反复改写相同题图。
- 新增答卷、成功重扫、作废或恢复改变有效集合后，旧 finalized 失效。空批次不能定稿。
- 新 state 原图路径相对批次。旧绝对路径按当前批次 raw/ 定位，不回读搬移前的同名文件；支持 Windows 路径搬到 macOS 读取。可读但越界的引用仍拒绝。

## 完整性检查

`audit_batch(batch_dir) -> AuditReport` 只读，不隐式修复或启用 OCR：

- 返回 ready/status/issues/files/summary/checked_at；files 是所有交付载荷相对路径及 SHA256，便于稳定快照。
- 核对 manifest、模板快照/底图、序号与题目唯一性、模板名版本、题号/小题/图片区域数量顺序、所有题图、学生字段和多条码、整页/原图。
- 核对 PDF 来源摘要和实际页码范围，来源路径与 manifest 对应。文件必须在批次目录内、可读取；图片需能完整解码。路径检查考虑符号链接及跨平台绝对路径。
- 未处置异常、processing、重判失败、未结算、缺图/坏图/越界/题目缺失均阻止交付。
- OCR none 允许；pending 阻止；failed 允许带明确失败清单交付。识别警告及已作废项进入清单，不冒充正常无警告。
- 交付最小单位为一批次。作废项保留显式处置记录；存在的异常证据随附，缺少旧作废证据记警告。

## 固定交付目录

`export_delivery(batch_dir, target) -> Path`：

- 拒绝覆盖已有目标，拒绝把目标放进源批次。
- 先检查，再仅复制检查器确认的当前载荷到目标同级临时目录；不复制 acquisition/、attempts/、state/ 等运行缓存和历史尝试。
- 对照源文件摘要检查复制期间变化，并重新检查副本；不满足时删除本次临时目录，不发布半成品。
- 副本 manifest 标记 `delivery: {sealed: true, revision: <uuid>, ...}`，生成 delivery.json（检查结果、警告/排除清单及摘要表），最后原子重命名。
- 固定目录可搬移、可在结果页查看，但不能继续扫描、重扫或 OCR 写入。后续修改在原工作批次进行，重新生成一个目录。
- 已生成目录的检查还核对 delivery.json 摘要表，检测意外修改；不是数字签名，也不承诺防恶意篡改。

## 界面与命令行

- 结果页有“检查交付”“生成交付目录”及清晰状态；操作在后台，回调属于原批次，活动采集/结算时不允许生成。
- 使用统一图片查看器核对每题、区域、任意学生字段及条码，支持 JSON；图片按选择读取，避免整批加载。换批次/单面切换/坏图时清空旧画面。OCR 失败可进入“有警告”筛选。
- CLI 增加 `check --batch` 和 `deliver --batch --out`，失败返回非零，recognize 有未结算异常也返回非零并保留输出目录。
- 保存默认扫描设置后，就绪页立即采用；正在运行时延后到本轮结束，当前采集参数不被中途改写。

## 边界

支持目标仍是 A3 及以下，包括 390×270 mm 的 8K。复用模拟卡、PDF 与 mock OCR，先失败测试再实现，最后完整回归、独立审查和 200 份样卡回归。真实扫描仪、全纸幅识别质量、600 DPI 千张性能、安装包及业务协议仍不在本包验收范围。
