# 工作包 3：采集、重扫与 OCR 可靠性

用户已授权继续下一工作包。沿用 Python/PySide6、图像源、流水线、批次目录与现有模拟数据；共享 main 工作区保留前两包改动，不提交、推送或打包。

## 目标与选择

已接收页面先有磁盘证据；暂停不阻塞识别回收；停止排空已接收页并等待设备释放；重扫失败保留旧答卷；旧 OCR 请求不能覆盖新结果。

选择在现有目录协议上增加采集暂存、重扫事务日志和 OCR 任务代次。仅扩大内存队列无法保证退出恢复；引入数据库或重写完整流水线超出本包需要。原始业务目标、A3 及以下含 390×270 mm 8K、不评分、不做上传/ZIP 均不变。

## 采集与暂停

- 扫描前校验模板面数与单双面配置；关键设备能力失败不能静默沿用默认值。设备实际模式应与请求一致。
- TWAIN 回调中先保存页面及可恢复元数据，再向队列传文件描述信息，避免无界整页数组积压。扫描输入绑定本批次 `acquisition/`，文件不依赖系统临时目录存活。
- 轮次与扫描尝试隔离；不跨轮拼接缺面。未登记的暂存页在批次重开时恢复成有原图的待重扫异常。重扫采集保留目标序号，不冒充新学生。
- 用独立且有界的输入读取任务配合流水线轮询回收 worker 结果；设备事件处理完成后才允许源继续下一轮。
- 停止只停止新增采集，排空已进入采集存储的页面与尾部半份，再结束识别。文件输入停止则不再读取新文件。
- 设备线程未退出时保持占用；不能再次扫描或重扫。驱动超时要明确显示，后续确认释放后才回到就绪。真机能力和驱动取消时序仍需 Windows 设备验收。

## 重扫与恢复

- 单份重扫先在隔离的尝试目录保存原图、执行识别；新图缺面、损坏、写入失败或识别失败时不改动旧有效记录及其证据。
- 成功后按持久化事务日志提交替换。旧证据留在尝试历史中；提交失败回滚；进程中断后打开批次可依据事务日志完成恢复，不依赖内存。
- 保持现有成功结果目录、manifest 和 state 使用方式；原图及来源路径随提交正确更新。
- 恢复解析完整序号，不截断 10000；损坏中间量隔离到对应答卷，不能使整批无法打开。
- 本包用“整份重扫原序号”处理缺面，不推测学生归属做自动补面。

## 控制器与界面

- 开始、停止中、重扫、结束批次均有同步占用状态，不能趁后台命令尚未执行重复启动。
- 流水线事件通过批次会话身份中转，迟到的旧事件不更新新批次。
- 新建/重开批次的 worker OCR 开关与实际队列一致；不改写历史已完成转写，未完成项保持可恢复。后补做由明确的重试/补做入口触发。
- 结果页单项、批量重试归属具体结果或批次；换对象后旧回调不刷新错误对象。退出包含这些重试任务的取消管理。

## OCR

- 首次队列、单项重试、批量重试共用任务认领和回写机制。有效身份包含结果路径、题/字段、输入内容和任务代次。
- 重复投递不重复请求；取消、内容更新或新代次后，旧成功和旧失败均不能回写。
- 代次与输入信息持久化于结果，在 JSON 文件锁内比较后更新；重新判定保留这些 OCR 身份元数据。
- 正常 close 等待并完成任务；取消关闭使未完成项可继续恢复，不把取消写成虚假的成功。
- 不发真实付费 OCR 请求，测试复用本地 mock 服务及受控阻塞客户端。

## 验证与边界

先新增失败用例再修改。设备使用替身验证配置、轮次、落盘、停止与释放；模拟写盘失败、半份、进程恢复、重扫提交失败、迟到事件、旧 OCR 晚返、重复重试。最后跑整套快速测试、原有 200 份模拟回归和界面检查。

不把这些结果表述为真实扫描仪、千张/600 DPI 性能或 Windows 安装包已验收。批次最终交付检查、坏图核对和完整分发验收留到下一包。
